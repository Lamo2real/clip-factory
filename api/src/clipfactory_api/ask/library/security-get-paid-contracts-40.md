## Get paid (CONTRACTS §40)

Get paid shows the owner each place's payout steps, whether money can reach him, and what Google and Whop say they
sent to his bank ([CONTRACTS.md §40](CONTRACTS.md#40-get-paid-set-up-payouts-see-if-you-can-get-paid-and-what-reached-your-bank-owner-request-2026-11-21),
[ADR-64](DECISIONS.md#adr-64-get-paid-payout-records-count-as-sent-to-your-bank-statuses-say-how-they-are-known-the-bank-waits-for-the-owner),
[ARCHITECTURE.md flow 23](ARCHITECTURE.md#23-get-paid-payout-steps-honest-statuses-and-money-sent-to-the-bank-contracts-40-adr-64)).
It adds two optional, read-only connections and no IAM, table, Lambda or Terraform-made secret.

| What | How it is protected |
|---|---|
| Bank, card and tax numbers | Clip Factory never asks for them, never stores them and has no field for them: every payout is set up on the place's own pages (AdSense for YouTube, Meta, TikTok, Stripe, Whop). The bank part ([§40.5](CONTRACTS.md#405-your-bank-waits-for-the-owners-choice)) is not built; until the owner chooses a source, no builder writes bank code, items, routes, secrets or infra. Its shape is already least data: only matched credits (date, amount, currency, place, the last 4 of the account), never a balance, a debit, other people's names, the payment text or a full account number or IBAN. |
| Money moves | None. Clip Factory only reads. The AdSense permission is `adsense.readonly` ("View your AdSense data"); Whop's are `openid user:balance:read payout:withdrawal:read payout:destination:read identity:read`, and Clip Factory never asks Whop for `payout:withdraw_funds`, `admin` or any write permission. |
| The three new secrets | `cf-prod/platforms/adsense/token` (`accessToken`, `expiresAt`, `refreshToken`, `scope`, `clientId`, `accounts`), `cf-prod/platforms/whop/app` (`clientId`, `userId`, `savedAt`) and `cf-prod/platforms/whop/token` (`accessToken`, `expiresAt`, `refreshToken`, `scope`, `whopUserId`). Created at runtime with `CreateSecret` (tags `app=cf-prod`, `platform`) under the existing prefix, never in Terraform, so a deploy can't touch them; never in DynamoDB, logs, responses, URLs, live events, push messages or the browser. |
| Who can reach them | Today's grants already cover them, so IAM is unchanged. AdSense token: written by `cf-prod-hooks` (the callback; create or put) and `cf-prod-money` (refresh; put), read by `cf-prod-money`, deleted by `cf-prod-api` ("Stop payment reading"). Whop app key: written by `cf-prod-api`, read by `cf-prod-hooks` (callback), `cf-prod-api` (connect) and `cf-prod-money`. Whop token: written by `cf-prod-hooks` (callback) and `cf-prod-money` (rotation; put), read by `cf-prod-money`. As with Content Rewards, the prefix grants are wider than needed and that is accepted (one owner): by the same prefix grants `cf-prod-clip-flow` and `cf-prod-stats` can also read all three and put `…/adsense/token` and `…/whop/token` (the `token-*` pattern), and `cf-prod-api` can read, write and delete all three, although their code never calls AdSense or Whop; narrowing it would mean renaming every platform secret. |
| AdSense is its own connection | The grant must come from the Google account that owns AdSense for YouTube, which may not be the YouTube one, so it is `PAYCONN#adsense` with its own token, never merged into the YouTube connection: it never touches `ACCOUNT#youtube`, the YouTube token, `SETUP#youtube` or `MONEYSTATE#youtube`, and Clip Factory never compares the two Google accounts. The authorize URL asks for the AdSense permission only, with `prompt=consent select_account` and **no** `include_granted_scopes`. The code exchange is done by `getpaid/grants.py` itself (never `providers.exchange()`), only `adsense.readonly` is checked, and a refused, failed or reused code, a missing permission, an account with no AdSense (200 with no accounts, or another 403) or a switched-off API (`accessNotConfigured`, `SERVICE_DISABLED`) writes nothing. |
| Stopping AdSense reading | "Stop payment reading" deletes Clip Factory's AdSense token and sets `PAYCONN#adsense` to `not_connected`. It makes **no** call to Google's revoke endpoint, because Google's revoke ends every permission the user gave the app and would also end the YouTube posting and money connection when it is the same Google account. The `PAYSTATE#` and `PAYOUT#` records stay (records of real money); a stopped connection is no longer fresh, so nothing on screen is built from them. A changed YouTube app key, `invalid_client` or `unauthorized_client` marks it `needs_reconnect` (`keys_changed`); `invalid_grant` marks it `token_dead`. Nothing is deleted. |
| Connect Whop | The owner makes his own Whop app (a public client: no secret). Sign-in is OAuth 2.1 with PKCE S256 from Whop's own metadata, read by the API (the browser never calls Whop), with the same signed single-use state as §17 (`OAUTH#{nonce}`, `platform: "whop"`). `whop` is accepted only on `/oauth/{platform}/callback`, never on `/hooks/{platform}`. Every call to Whop sends `Api-Version-Date: 2026-11-20`. Whop's refresh token rotates on every use, so a refresh runs only under the lease on `PAYCONN#whop` and is written back put-only, checked against `tokenVersionId` (the Content Rewards rules); `invalid_grant` means `needs_reconnect`, never a delete. A new Whop key while connected deletes the old app's token. "Stop reading Whop" revokes at Whop when the metadata has a revocation endpoint (best effort), deletes the token and keeps the key. The whole part is behind `WHOP_CONNECT` (Terraform `whop_connect_enabled`, default `false`): while off, its routes answer 503 and the card says "Coming soon". |
| Redirects | Both callbacks answer with a fixed result code only (`payments_allowed`, `payments_denied`, `payments_missing`, `payments_no_account`, `payments_api_off`, `payments_error`; `whop_connected`, `whop_denied`, `whop_missing`, `whop_expired`, `whop_error`) to a fixed page, so nothing from the request is reflected. The code, state and query are never logged. |
| What the API answers | Every Get paid route reads stored items only (no platform, Google or Whop call), except the two connect routes (Whop's metadata) and "Stop reading Whop" (Whop's revoke, best effort); "Stop payment reading" only deletes Clip Factory's AdSense token and never calls Google. No answer carries a token, a client secret, a raw platform answer, Whop's trace code or an AdSense publisher id beyond its last 4. Alert messages from Google (which may hold HTML) are stored as plain text of at most 300 characters. |
| Notifications | "Money on hold or sent to your bank" (`notify.getPaid`, default on) says only what happened ("Your YouTube money is on hold. Tap to see why."): no link, secret or account number in a message, and no notification for old money on the first read. |
