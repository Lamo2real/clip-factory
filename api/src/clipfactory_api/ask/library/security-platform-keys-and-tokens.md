## Platform keys and tokens

The owner pastes each platform's app keys into the setup ([SETUP_POSTING.md](SETUP_POSTING.md)) and presses Connect
([CONTRACTS.md §17.4–17.6](CONTRACTS.md#174-api-all-jwt-5-errors-routessetuppy-package-clipfactory_apioauth)).

| What | How it is protected |
|---|---|
| App keys (`clientId`, `clientSecret`, `configId`) | Sent once over HTTPS to `PUT /v1/setup/{platform}/keys` (JWT), written to Secrets Manager `cf-prod/platforms/{platform}/app`, never returned. Responses, DynamoDB and live events carry only masked hints (first 6 and last 4 characters of the public id, "••••" and the last 4 of a secret). The paste box is cleared after saving. |
| Account tokens | Written by `cf-prod-hooks` after the code exchange to `cf-prod/platforms/{platform}/token`; refreshed by `cf-prod-clip-flow` and `cf-prod-stats`. Instagram signs in with a Facebook **user** access token (exchanged for the long-lived one), but only the chosen Page's access token is kept here, with the Instagram account id and Page id; the user token is never stored. Posting and numbers use the Page token. Meta's several-account choices wait in `…/pending` for at most 30 minutes. Never in DynamoDB, logs, responses, URLs, WebSocket events or the durable execution history (steps return ids, not tokens). |
| Secret lifecycle | Created at runtime with `CreateSecret` (tags `app=cf-prod`, `platform`), updated with `PutSecretValue`, deleted with `ForceDeleteWithoutRecovery` on Disconnect or key delete. Logs name the secret, never its value. |
| Who may read them | `cf-prod-api` (create, put, get, describe, delete on `cf-prod/platforms/*`), `cf-prod-hooks` (public, so the narrowest: get and describe only on the `app` secrets `cf-prod/platforms/*/app*`; create, put, get, describe on the token secrets `cf-prod/platforms/*/token*`; the same plus delete on the `pending` secrets `cf-prod/platforms/*/pending*`. No `-` before the `*`, because for a secret that does not exist yet Secrets Manager checks the bare name, and the callback needs "not found", not "access denied", to create it), `cf-prod-clip-flow` and `cf-prod-stats` (get on `cf-prod/platforms/*`, but put only on the token secrets `cf-prod/platforms/*/token-*`, the ARN pattern Terraform passes in as `platform_token_secrets_arn`). Only `cf-prod-api` can write or delete the `app` secrets; only `cf-prod-api` and `cf-prod-hooks` can write the `pending` secrets. `cf-prod-hooks` reaches only the `HOOK#`, `OAUTH#` and `USER#` partitions of the table (`dynamodb:LeadingKeys`); after a connect it may set the owner's waiting posts to queued and start `cf-prod-clip-flow` (any qualifier of that one function, no other), so a post never goes anywhere the owner did not upload it to (CONTRACTS §17.6). The job flow, the agent, the WebSocket Lambdas, `cf-prod-learn` and `cf-prod-autopost` have no Secrets Manager access. |
| Connect state | `state = v1.{nonce}.{exp}.{HMAC-SHA256}` with the key in `cf-prod/oauth/state-key` (generated by Terraform as a write-only value, never in its state), valid 10 minutes, bound to the platform, and consumed once with a conditional delete of `OAUTH#{nonce}`. A tampered, expired, reused or cross-platform state ends as "That took too long". |
| PKCE | S256 for YouTube and X. The verifier is derived from the nonce with the state key, so it is never stored or sent to the browser. TikTok and Meta use the client secret on the server instead. |
| Redirects | Every platform has one exact redirect URI, `{hooks_url}/oauth/{platform}/callback`, compared exactly by the platform. The callback always answers `302` to `{app_url}/settings/posting/setup/{platform}?result={code}` with a code from a fixed list: nothing from the request is reflected, so it cannot be an open redirect. `Cache-Control: no-store`, `Referrer-Policy: no-referrer`. The code, state and query are never logged. |
| Scopes | Only what posting and numbers need (CONTRACTS §17.7). A missing permission is detected and reported; Meta calls send `appsecret_proof`. |
| Disconnect and data | Disconnect revokes the token where the platform allows it, deletes the token secret and marks the account `not_connected`. For YouTube it also removes stored YouTube numbers (`forget`), as YouTube's Developer Policies require after revocation. Facebook keeps only the Page token, which cannot revoke the app, so the owner removes the app in Facebook's Business integrations settings ([After setup](SETUP_POSTING.md#after-setup)). |
| TikTok verification file | `POST /v1/setup/tiktok/verification-file` accepts only `tiktok*.txt` names and at most 4 KB of printable text, and writes only `tiktok*` keys in the web bucket. |
| Public pages | `about.html`, `legal/privacy.html` and `legal/terms.html` are static and hold no data. |
